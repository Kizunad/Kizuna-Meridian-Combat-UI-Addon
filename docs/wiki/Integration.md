# 整合接口与方案问题

## 当前开发装配接口

首版与 v1.1 视角交付使用冻结提交 `89e37ec0a35748297d7ffd281231d2eb9537065f`，历史交付记录保留该事实。
图标栏改为默认引用相邻功法库与 Framework 工作区的公开 API。
原因是通宵整合的正式宿主已经使用 `TechniqueHost.Inspection(body, heldItems)`，与旧快照二进制不兼容。
这依赖功法库尚未提交的开发接口；不再声称能仅配合 89e37ec 运行，依赖状态见图标栏交付记录。
使用 `TechniqueService.cast/registry`、`TechniqueHostDirectory`、`TechniqueState`、`TechniqueBinder`
和 `TechniqueFabric.KNOWN_CHANGED`，未修改依赖源码。
目录与图标均使用最高已学且仍存在的精确版本。
费用、持物、承接与事务提交没有公开的统一预检入口，HUD 只投影身体绑定和冷却，
其余失败保留施放动作栏反馈，避免复制功法服务内部规则。

功法宿主返回 `BODY_PAUSED` 时，服务端只告警一次，发送空的已学功法投影覆盖旧内容，并停止该连接的自动查询；不反复发送动作栏错误。重新注册接收通道不会解除暂停，只有重新登录才重新查询宿主。其他自动同步异常也只报告首个堆栈，成功后清除故障标记。

方案略写的 `CastRequest` 实际还要求 `body_id` 与精确功法版本。
本附属通过公开宿主 inspect 补身体身份，按已有知识选择精确版本，再让服务完整校验，防止目录升级自动授予新版。
方案没有定义多版本选择与已移除内容过滤，本仓采用「目录仍在的最高已学版本」并过滤缺失引用。
公开 `KnownEntry.name` 来自功法描述，并非独立显示名称；首版沿用服务结果。以后若需要短名称，应由功法定义提供专用字段。

方案没有给 KNOWN 包上限，本仓选定 1 MiB / 4096 条；超过规模时拒绝整份并记录日志，未加入分片协议。
所有操作状态均用动作栏，但十槽 `list` 用聊天反馈，避免同一帧十条动作栏相互覆盖。
JOIN 不保证通道已注册，因此同时监听接收通道注册事件补发初始列表。

## Human 宿主

本附属不硬依赖 Human，不读取 Human 的内部身体映射。
Human 整合须通过 `meridian_technique_host` 按实体 UUID 唯一认领身体，提供 inspect、可信活动提交与效果入口，沿用功法框架现有契约。
须确保 JOIN 认领时序、断线前取消活动、宿主可信时钟及 INPUT 零方向朝向解释正确；这些不是客户端提供的参数。
GameTest 使用真实框架原子活动处理器加测试宿主，不证明 Human 的身体、费用、冲量、基础功法或动画已整合。
首版无需为战斗 UI 新增 Human 接口，实际内容与世界效果仍需 Human 和功法目录提供者。

## PA 架势动画钩子

本地公开事件 `CombatStanceEvents.CHANGED` 在客户端主线程发布 `CombatInput.State.ACTIVE/OUTSIDE`。
主动进出、死亡、旁观、断线都经过该钩子；开界面暂停输入不发布退出。
它是当前输入状态的变化通知，订阅者应在客户端初始化期间注册。

后续接入 PA 的 stance_idle 等 22 段动作，还需明确移动方向、速度、冲刺/潜行到动画的映射，入退过渡、部位遮罩、优先级和功法动作覆盖规则。
PA 的逐帧运动适配应由独立订阅者维护；这里不为尚未实现的动画增加状态字段。
若要求他人可见，须另行定义服务端架势同步和追踪玩家广播契约；现有两个通道不承担该功能。
首版未添加 PA 依赖，也不播放任何架势动画。

## v1.1 视角取舍与接口需求

按交接文末越肩小节解释「出招沿人物当前朝向」：越肩的非零请求改为人物当前正前方，
第一人称保留首版有输入时携带移动方向的行为；两模式无输入都维持零向量契约。
功法库与 Human 无需新增接口，但 Human 的 INPUT 零方向处理必须读取人物当前朝向，而不能读取客户端镜头。
功法目标选取同样应使用实体眼位与实体角度，不应新增取相机的路径。

`V` 是独立可改绑模式键，架势内消费原版 F5，避免第三种原版视角覆盖两模式；架势外 F5 恢复原版流程。
进入第一人称或越肩时只记录一次进入前视角；退出或断线恢复，不把独立镜头角回写人物。
越肩时俯仰保持人物原值，不提供另一套人物俯仰控制键。镜头距离和偏移使用文件参数，没有新增配置界面。

纯 Java 的 `CombatView`、`CombatViewMath`、`CombatCamera` 分别负责会话、运动换算、几何与收缩，
`CombatViewSettings` 和原有配置路径负责校验与持久化。Fabric 控制器和五个客户端 Mixin 只连接原版对象。
没有第三方视角模组、服务端架势同步、相机网络包或 Human/PA 硬依赖，也没有改相邻仓库源码。

## Human-UI CombatJourney 待验

真实客户端按键验收按交付范围留给 Human-UI：R 条件与改键，架势内 1–9 不切物品、0 对应第十槽，架势外原版行为，滚轮正常，界面暂停与死亡/旁观/断线退出。
还应覆盖跨服分档、移动视角方向和真实基础功法的费用/冷却/世界效果。
v1.1 还须验证 V 改键与模式记忆、鼠标绕看时人物和服务端角度不变、WASD/斜向/疾跑跳跃与限速转身、
转身中施放方向、左键/功法目标、F5 消费、全部退出原因的视角恢复、右肩画面构图与真实墙角/低顶。
不同 FOV、近裁面、半砖/栅栏、骑乘、游泳/滑翔和其他输入/相机模组兼容需实机核对。
原版自动跳跃仍保留人物前方判定，转身未完成时可能延后触发，不等于移动基向量换算失败。
本仓验证纯状态机、Brigadier 和专用服务端正式通道；客户端加载烟测的范围见 [验证记录](Verification.md)，未运行真实玩家旅程。
